# PyLab — задачи и автопроверка по Python

Django-проект: преподаватель ведёт группы, уроки и задачи с тестами,
студенты пишут код в браузере, запускают его и отправляют на проверку.
Все настройки — в `constants.py`, переменные окружения не нужны.

## Запуск на ноутбуке (Ubuntu) для пары в локалке

```bash
cd pylab
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
sudo apt install bubblewrap        # песочница для кода студентов
python manage.py migrate
python manage.py runserver 0.0.0.0:8000
```

1. Откройте `http://127.0.0.1:8000` — появится страница первого запуска, создайте аккаунт преподавателя.
2. Зайдите в раздел **Песочница** и нажмите «Проверить песочницу». Все пункты должны быть зелёными.
3. Узнайте свой IP в локалке: `ip -4 a` (что-то вроде `192.168.1.25`).
4. Откройте порт: `sudo ufw allow 8000` (если ufw включён).
5. Студенты открывают в браузере `http://192.168.1.25:8000` и входят по выданным логинам.

Интернет на паре не нужен: редактор и шрифты лежат в `static/`.

## Порядок работы

1. **Группы** → создать группу (МИК-241) → «Добавить списком», вставить ФИО построчно.
   Логины и пароли покажутся один раз — распечатайте их. Потерянный пароль: кнопка «Новый пароль».
2. **Уроки и задачи** → новый урок → «Добавить задачу». Тип «Автопроверка» — тесты ввод/вывод,
   проверка до первого упавшего теста, как в ICPC (пробелы в конце строк не важны).
   Тип «Вручную» — решение ждёт вашей оценки.
3. Урок открывается для группы кнопкой с её названием (жёлтая — открыт),
   отдельная задача — галочкой «открыта».
4. **Отправки** — все решения с кодом, фильтры, перепроверка, «Зачесть / Не зачесть» с комментарием.
5. **Сводная** — таблица «студент × задача» с числом попыток.

## Вход студентов по ID и журнал IP

**Группы → «Загрузить список из расписания»**: вставьте список как есть
(`1) ФИО (МИК241) 49562`). Группа «МИК241» найдётся среди ваших («МИК-241») или создастся.
Студенты входят, вводя только свой ID. Повторная загрузка обновляет ФИО и группу.

Все входы, запуски и отправки пишутся в **Журнал** с IP-адресом. Вверху журнала —
совпадения: один ID с нескольких компьютеров и несколько студентов с одного компьютера.

Необязательные строки для `constants.py`:

```python
ID_LOGIN_ENABLED = True                     # False — вход только по паролю
ID_LOGIN_ALLOWED_NETS = ["192.168.0.0/16"]  # вход по ID только из этих сетей ([] — отовсюду)
TRUST_X_FORWARDED_FOR = False               # True, если сайт стоит за nginx
```

Онлайн обязательно ограничьте `ID_LOGIN_ALLOWED_NETS` или отключите вход по ID:
ID из расписания знают все одногруппники.

## Песочница

Код студентов запускается через bubblewrap: без сети, файловая система только
для чтения, свой `/tmp`, лимиты времени, памяти, размера вывода и числа процессов.

- `SANDBOX_USE_BWRAP = False` — запуск без изоляции. Только для проверки на своём компьютере
  (и на Windows, где bubblewrap нет). Для пар и онлайна — всегда `True`.
- Если проверка пишет ошибку `bwrap: setting up uid map: Permission denied`
  (бывает на Ubuntu 24.04 из-за ограничений AppArmor), выполните:
  `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`
  и для постоянства добавьте эту строку без `sudo sysctl -w` в `/etc/sysctl.d/60-pylab.conf`.

### Отдельный пользователь для кода (рекомендуется онлайн)

```bash
sudo adduser --system --no-create-home pylabrun
sudo mkdir -p /srv/pylab_tmp && sudo chown $USER /srv/pylab_tmp && chmod 755 /srv/pylab_tmp
echo "$USER ALL=(pylabrun) NOPASSWD: /usr/bin/bwrap" | sudo tee /etc/sudoers.d/pylab
```

В `constants.py`: `SANDBOX_RUN_AS = "pylabrun"`, `SANDBOX_TMP_DIR = "/srv/pylab_tmp"`.
Потом снова «Проверить песочницу».

## Выкладка онлайн

В `constants.py`:
- `DEBUG = False`, новый длинный `SECRET_KEY`;
- `ALLOWED_HOSTS = ["ваш-домен"]`, `CSRF_TRUSTED_ORIGINS = ["https://ваш-домен"]`;
- `DB_ENGINE = "postgres"` и доступы `PG_*` (раскомментируйте psycopg в requirements.txt).

```bash
python manage.py migrate
python manage.py collectstatic
gunicorn config.wsgi -w 1 --threads 16 -b 127.0.0.1:8000
```

Важно: **один процесс gunicorn (`-w 1`)** с потоками. Очередь проверки живёт внутри
процесса, и лимиты `JUDGE_WORKERS` / `MAX_PARALLEL_RUNS` действуют на весь сервер
только при одном процессе. Для учебной нагрузки этого с запасом хватает.

nginx: раздаёт `/static/` из `staticfiles/`, остальное проксирует на `127.0.0.1:8000`.

## Если что-то зависло

Отправки «в очереди» после перезапуска сервера возвращаются в очередь автоматически
при первой новой отправке, либо вручную: **Отправки** → «Вернуть зависшие в очередь».

## Структура

```
constants.py          все настройки
config/               настройки Django
core/models.py        группы, пользователи, уроки, задачи, тесты, отправки
core/views_teacher.py страницы преподавателя (/t/…)
core/views_student.py страницы студента, запуск и отправка
core/judge/           песочница, сравнение вывода, очередь проверки
templates/core/       шаблоны
static/               CSS, JS редактора, CodeMirror и шрифты (локально)
```
